# Hareka ブログ記事ガイドライン

## 読者
HubSpot導入・移行・活用を検討している経営者・営業責任者・CRM担当者。エンジニア向けには書かない。

## 記事の型（全記事共通）
1. 導入：相談で一番多いパターンから入る。機能説明から入らない
2. 実際の難所：1つを深く。広く浅くにしない
3. やるべきケース／見送るべきケース：必ず両方書く。「見送るべきケース」を正直に書くことが差別化
4. 数字：期間・件数・金額のいずれか、最低1つ
5. FAQ：4問。AI検索が拾えるよう、質問文は検索されそうな自然文で
6. 締め：判断基準を1行で言い切る
7. CTA：既存記事のパターンに合わせる

## 必須要素（1つでも欠けたら公開しない）
- 岩間しか書けない要素が最低1つ（具体的な数字、実案件の難所、見送るべきケースの判断基準のいずれか）
- 事例（/cases/）への本文内リンク1本以上
- 関連するピラー記事またはサービスページへの本文内リンク1本以上
- タイトルは全角32文字以内。「検索キーワード＋ビジネスインパクト1つ」の型

## 禁止表現
- 「〜と言われています」「一般的には」「〜かもしれません」「〜と聞いています」→ 断定調で書く
- 「個人コンサル」→「代表が一貫して担当する体制」
- 価格（Harekaの支援費用）は書かない
- 筆者の経験件数（多い・少ないどちらも）は書かない
- 競合ツール（Salesforce・Zoho・kintone・Zendesk等）を貶めない。「目的と状況で判断する」トーン

## 事実の扱い
- 実体験で確認できたことは断定する
- 公式ドキュメントに依拠する場合は「公式発表によれば」「公式ドキュメント上は」と出典を明示する
- どちらでもないことは書かない

## 製品名の表記
- Data Hub Professional（旧Operations Hub Professional）— 初出のみ旧名併記
- Sales Hub / Service Hub / Marketing Hub — プラン名（Starter / Professional / Enterprise）を明示

## frontmatter
既存記事（38・40・41）と同じスキーマ。updatedDate を使う場合は更新日を入れる。

## 公開前チェック
- npm run build エラーなし
- タイトル32文字以内
- 事例リンク・ピラーリンクが本文内にある
- 禁止表現をgrep
